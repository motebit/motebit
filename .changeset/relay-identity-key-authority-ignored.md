Relay: one rule for who may change what the relay believes an identity's key is, turning on one definition — the identity key as the relay can prove it (registry key, else recorded succession head, else a key the `motebit_id` commits to, else the one key every device agrees on; never a guess). A key succession is accepted only under the identity it rotates and only from that key; recording one re-keys the identity's device records and ends its open sessions in one transaction, so a rotated-away key stops verifying tokens; a guardian is installed only by a caller verified under the identity key and is never replaced by re-registration; a first registration establishes only a proven key; a caller is judged by the key captured when its token was verified; pairing's key-transfer route writes only the identity key; the receipt path no longer rewrites the registry key. `spec/identity-v1.md` §7.5 states the obligations.
