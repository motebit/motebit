A P2P settlement record names the worker the payment paid, the verifier checks the worker leg against that worker, and a failed payment is charged to the payer — never to the worker, never to anyone's `settlement_modes` (#959).

- **Payee.** `handleReceiptIngestion` signed every P2P `SettlementRecord` with `motebit_id` = the path agent. The runtime submits P2P tasks to the DELEGATOR's own endpoint, so every record named the payer. The payee is now the admitted, pinned worker (`p2pPayeeOf`: `target_agent`, else the executor relay's forwarded task worker), in the parent writer, `settleSubReceipt`'s P2P branch and the federated origin writer. A P2P receipt signed by anyone else settles nothing (the task stays open for the paid worker). Duplicate checks are task-keyed, so a sub-hop's row written first is seen and never re-written or dropped. Known residual, not changed here: a relay-mode row's `motebit_id` column is still the path agent while its signed body names the credited worker (pinned by a characterization test).
- **Verifier.** The worker leg matches only an exact-amount transfer to the payee's derived-bound address or its own registered address. Which relay verifies the worker leg is declared on the row (`p2p_worker_leg`: `local` | `remote`), not inferred from a missing registry row. A worker leg this relay owns but cannot check — no bound address, or a legacy row naming its own payer — is the new terminal status `unverifiable` (never `verified`, no penalty).
- **Attribution.** `downgradeP2pTrust` is replaced by `recordPayerFailure`: a failed worker leg or missing transaction adds one failure to the worker's own edge about the payer; a failed fee leg moves no agent edge. The payer's edge about the worker and every `settlement_modes` are left alone.
- **Historic rows (migration v48).** Signed/anchored records are not rewritten. `relay_settlement_payee_corrections` records the true payee beside a row that named its payer, derived from the unique signer of the archived receipt whose `result_hash` equals the record's `receipt_hash`; corrected rows the old verifier failed on the worker leg return to `pending`. Declared in the transparency declaration and `PRIVACY.md`.
