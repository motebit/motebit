`motebit delegate`: every 402 on every delegate path now names the remedy that clears it. `--plan` no longer reports a P2P-required refusal as "Insufficient balance" (it says the paid step settles P2P and, since `--plan` cannot pay P2P yet (#887), to send it with `motebit delegate --sovereign`); the relay's paid federated refusal now carries the stable `TASK_P2P_PROOF_REQUIRED` code, so it too points at `--sovereign`; x402 refusals and unknown coded 402s show the relay's own words; and a `--sovereign` 402 never suggests `motebit fund` (that path pays from your Solana wallet). `motebit fund` is suggested only where a deposit can clear the 402: `INSUFFICIENT_FUNDS`, or a codeless 402 (the x402 challenge, a facilitator outage) on self-delegation. A codeless 402 is the relay's x402 challenge whenever your spendable balance is below the price, whoever the worker is; for another agent a deposit only moves the refusal to `TASK_P2P_PROOF_REQUIRED`, so for a submission to another agent it points at `--sovereign` instead, and where the worker is not known (`--plan` routes by capability) it says both: `motebit fund` only if the relay routes the task to yourself, otherwise send it with `motebit delegate --sovereign`.

The REPL's `/delegate` now prints a remedy on a 402 (read through the shared `describeDelegateSubmit402`) instead of the relay's raw JSON body. `/delegate` has no `--sovereign` flag (everything after the target id is the prompt), so on a P2P-required refusal it names the runnable shell command instead: exit the REPL and run `motebit delegate --sovereign '<prompt>' --target <id> --capability <capability>`, filled with the prompt you typed (single-quoted, so a `!` cannot trigger shell history expansion), the target, and the capability that target charges for (else lists) on the relay, read from relay discovery (`motebit delegate` otherwise assumes `web_search`, which a worker that does not list it refuses). When the REPL cannot learn the target's capability, it says to replace `<capability>` with the one the worker lists. Every printed remedy is runnable on the path that printed it. Out of scope, by reason: `motebit withdraw` / `/withdraw` 402s are a withdrawal-side balance refusal (no task submission, so `INSUFFICIENT_FUNDS` is the only reading); `/invoke` and the AI-loop delegation render the runtime's classified `DelegationErrorCode` and message, never a raw relay body and never `motebit fund`; the daemon only posts worker results; `motebit smoke x402` drives the 402 challenge on purpose. No path retries or pays automatically on a 402.
