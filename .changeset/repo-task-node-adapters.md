Node adapters for the repo-task run (governed repo change, milestone B build step 2), not yet wired to a command: a git tree reader that reads only the tip's tree (`git ls-tree` / `git cat-file` with isolated git config and literal pathspecs); a git change stager that never writes the worktree — new content goes to git's object store as blobs (`hash-object -w`), and the change commit is built on a private index with every path on stdin (`read-tree`, `update-index -z --index-info`, `write-tree`, `commit-tree -p <tip>`), touching no worktree file, repository index or ref, and refusing (no commit) any tree that is not exactly the staged adds and modifies of 100644 blobs; no git process ever runs on the real git directory, so git never parses its config: every git call runs in an isolated session against a private empty repository (its config written by us, the real object store via `GIT_OBJECT_DIRECTORY`, alternates honoured for reads), with a per-call timeout (a call that times out, or whose git stops reading its input — an EPIPE now rejects instead of crashing the process; a call with no input gets no stdin pipe, so a git that exits before reading cannot raise EPIPE on a success — ends the session and removes its directory); the object directory is resolved without git (the `.git` entry or its `gitdir:` file, then `commondir`, each strict and no symlink) and the object format comes from the verified scope; the commit timestamp must be integer seconds (`@<secs> +0000`); and a durable JSON-lines receipt file. The governed-run receipts carry the call's real status (see the runtime changeset).
