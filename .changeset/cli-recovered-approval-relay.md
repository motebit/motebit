An approval recovered after a restart runs a relay-bound tool only under the relay it was approved under.

The daemon's approval queue now records, for every paused call, the relay it was decided under and whether its tool is relay-bound (migration #54, three nullable columns). Both writers — a goal turn's pause and a plan step's pause — copy these from the pause itself, never from the binding at write time. When an approval is decided after a restart, a relay-bound tool (`delegate_to_agent`, `discover_agents`, `retrieve_task_result`) runs only if the bound relay is the same relay with the same pinned key; otherwise the run ends "approved under another relay than the one bound now — not executed: relay_changed", and nothing is sent. Rows written before this release, and rows stamped under a relay URL that cannot be pinned, are refused for relay-bound tools; a pre-release row whose tool is not registered at restart is refused as "approved before relay recording and its tool is not registered now, so it cannot be checked against the bound relay — not executed". A `relay_changed` refusal the runtime itself made for a relay-bound tool is reported the same way as the drain's own and, like it, does not count as a goal failure; a tool's own failure, whatever its text, is still a counted failure. Each refusal says only what is known: another relay is bound, no relay is bound, the tool is not registered under the current binding, or no relay was recorded with the approval. The runtime half is in `runtime-recovered-approval-relay-ignored.md`.
