Withdrawal payouts: whether a payout landed is decided by the chain, a payout that cannot work is not offered, and a failed batch fire always has a settle door (#948, #949, #945).

**#949 — chain facts, never the relay's clock.** A Path 0 (Solana) payout now records every transaction it signs (signature + `lastValidBlockHeight`) BEFORE broadcast, through the #885 `beforeBroadcast` hook; a transaction the relay cannot record is not sent, and the claim is marked chain-recorded in the same transaction as `pending → processing`. `/admin/withdrawals/:id/reconcile` asks the chain about exactly those transactions: one landed ⇒ only `paid`, under that signature; every one failed or past its last valid block HEIGHT (or none recorded) ⇒ only `not_paid`; anything still able to land, or an unreadable chain ⇒ 409 (`chain_pending` / `chain_unreadable`). An outcome that contradicts the chain is 409 `WITHDRAWAL_RECONCILE_CONTRADICTS_CHAIN`. The old wall-clock horizon (send end + 150s + 5 min) is gone: during a cluster halt it let an operator refund a payout that then landed. A claim made before this change (no signatures recorded) opens only once the chain's height passes the first height this process read + 310 blocks. Path 0 sends only over a transfer that `recordsBroadcasts`. New tables `relay_withdrawal_chain_claims`, `relay_withdrawal_payout_attempts` (declared in the transparency declaration).

**#948 — Path 1 is disabled.** `X402SettlementRail.withdraw` put the idempotency key where the EIP-3009 signature belongs; no facilitator can execute that, and the relay holds no EVM treasury key to sign one. The rail is now structurally non-withdrawable (`supportsWithdraw: false`, no `withdraw`, no payout-horizon declaration; `X402_WITHDRAWAL_VALIDITY_SECONDS` removed), the Path 1 dispatch is deleted, and `POST /withdraw` to a 0x destination is refused 400 `WITHDRAWAL_DESTINATION_UNSUPPORTED` before any debit.

**#945 — no stranded batch funds.** A batch fire whose rail throws, reports the item failed, or whose process died mid-fire is recorded on a relay_withdrawals row in the same transaction as the queue row's terminal CAS: `processing` for a sent-mode rail (reconcile door), `pending` for a manual one (complete/fail). Crashed `firing` rows are recovered by the loop (never re-fired), not just logged; the tick rethrows so the supervisor records a failed tick.

`@motebit/wallet-solana`: `OperatorSolanaTransfer.sendUsdc` is replaced by `sendPayout` (a durable-nonce payout over a `DurableNonceLane`, with `DurableBroadcastHooks`); new `recordsBroadcasts`, `prepareNonceLane`, `broadcastNonceKill`, `getFinalizedStatus`; `SolanaRpcAdapter` gains optional `prepareNonceLane` / `sendUsdcDurable` / `broadcastNonceKill` / `getFinalizedStatus` (implemented by `Web3JsRpcAdapter`), with the types `DurableNonceLane`, `NonceLaneState`, `DurableTransactionRef`, `DurableBroadcastHooks`, `FinalizedSignatureStatus`, `DurableSendResult`, `NonceKillResult` and `NONCE_ACCOUNT_SEED` (#990).

`@motebit/wire-schemas`: the `account-withdraw-request` `destination` description no longer offers EVM 0x (Path 1 retired, #948; deferred-with-trigger — real demand AND a treasury-custody design for EVM signing). `spec/schemas/account-withdraw-request-v1.json` regenerated.

**#949 round 2 — absence is evidence only inside retained history.** Many RPC nodes prune transaction history, and a pruned landed payout reads as absent. Each recorded transaction now carries the slot read before signing (`SignedTransactionRef.recentSlot`, set by `Web3JsRpcAdapter`); an "absent, past its last valid height" read decides `not_paid` only when the node's first available slot (`getFirstAvailableBlock`) is at or before that slot less `LANDING_SLOT_MARGIN`. Otherwise the verdict is `history_pruned`: `not_paid` is refused 409 `chain_history_pruned`, and `paid` naming a recorded signature is accepted. `@motebit/wallet-solana`: `historyCoversLanding`, `LANDING_SLOT_MARGIN`, `SignatureOutcome` rpc_error `historyPruned`, `getFirstAvailableSlot` (adapter + `OperatorSolanaTransfer`); the adapter's own `getSignatureOutcome` applies the same rule to refs that carry `recentSlot`.

**#949 round 3 — no payout without a door.** `Web3JsRpcAdapter` retries the pre-blockhash slot read once and, when a payer records broadcasts (`beforeBroadcast`), signs and sends nothing without it — "nothing was broadcast" stays a clean verdict (C1). An attempt recorded without a slot is still decidable: `earliestLandingSlot` falls back to `lastValidBlockHeight − LANDING_HEIGHT_WINDOW` (every block's slot is at least its height), so a node holding deep history proves it absent. `OperatorSolanaTransfer.recordsBroadcasts` now also requires `getFirstAvailableSlot` — a transfer that can never prove absence is never used for Path 0.

**#949 round 4 — absence is authoritative only from the node's local ledger.** agave's `getFirstAvailableBlock` is min(blockstore, BigTable) — near genesis on a BigTable node — and reads a blockstore error or a ledger with < 2 roots as 0, while a historical status lookup that misses the local ledger asks BigTable and swallows any error as absent: a landed payout could read expired with history "covered". The retention edge is now `getLocalLedgerFirstSlot` (`minimumLedgerSlot`, blockstore-only; errors are errors) plus `LOCAL_LEDGER_EDGE_MARGIN` (4096 slots: the local search starts at the second root, and cleanup purges statuses ahead of their metas). `SolanaRpcAdapter.getFirstAvailableSlot` / `OperatorSolanaTransfer.getFirstAvailableSlot` are renamed `getLocalLedgerFirstSlot`; `recordsBroadcasts` requires it.

**#949 round 5 — absence in history is never evidence of non-payment (supersedes rounds 2–4 and the legacy height bound).** Five rounds each found another way a history read reports a landed payout as absent (pruning, a missing slot, BigTable's swallowed errors, cleanup lag, a snapshot jump); the law is now that a refund needs POSITIVE evidence for every recorded transaction: a status found with an error, or the FRESH verdict — `getSignatureStatuses` without `searchTransactionHistory`, at `finalized`, with `minContextSlot`, read while the finalized status cache still covers the whole landing range (`lastValid + 11 ≤ H_f ≤ lastValid + 130`; agave keeps the newest 300 roots, `status_cache.rs` `MAX_ROOT_ENTRIES` / `purge_roots`, and a blockhash is valid for `MAX_PROCESSING_AGE` = 150 blocks, `bank.rs`), and a second finalized height read bound by the answer's slot. The verdict is recorded durably per attempt (`fresh_verdict`, `fresh_context_slot`, `fresh_landed_slot`, `fresh_checked_at` on `relay_withdrawal_payout_attempts`) by a supervised 10 s sweep (`withdrawal-fresh-verdict`) and by the reconcile door. Everything else is unknown: `not_paid` is refused 409 (`chain_pending` / `chain_unreadable` / `chain_no_positive_evidence`, the last pointing to #990), and `paid` naming a recorded signature is always accepted. A legacy claim (no recorded signature) is `reconcile_decided_by: "operator_attested"`: `not_paid` is refused, `paid` is accepted. Removed: `SignedTransactionRef.recentSlot`, `historyCoversLanding`, `earliestLandingSlot`, `LANDING_SLOT_MARGIN`, `LANDING_HEIGHT_WINDOW`, `LOCAL_LEDGER_EDGE_MARGIN`, `getLocalLedgerFirstSlot`, `getBlockHeight`, `LEGACY_BROADCAST_HEIGHT_BOUND`, the `chain_height` / `chain_history_pruned` states. The honest-path cost: a payout that never landed and whose fresh window closed with no verdict recorded (the relay and the operator both missed that minute) stays `processing` until #990 (a durable-nonce kill transaction).

**#949 round 6 / closes #990 — decided by consensus rules, not by RPC reports (supersedes round 5's fresh verdict).** Released agave (v2.3.13 … v4.0.0) ignores `commitment` and `minContextSlot` on `getSignatureStatuses` and answers from the processed bank, so round 5's fresh verdict never recorded a death (1a: a payout that never landed was stuck for good), took a processed minority-fork status as landed (1b) and a fork error as failed (1c: refunded, then the payout landed). Path 0 payouts are now **durable-nonce transactions**: the treasury's nonce account (seed-derived, created idempotently, rent 1 447 680 lamports) is the lane; each payout signs `nonceAdvance` first over the lane's value N read at finalized, is recorded with N before broadcast, and is never re-signed, so at most one transaction over N ever lands. Only a per-status `confirmationStatus: "finalized"` decides (agave `rpc.rs` `get_transaction_status` / `is_finalized`; a failed durable transaction still advances its nonce, `svm/src/rollback_accounts.rs`): a finalized ok payout ⇒ completed; a finalized failed payout, or a finalized KILL (`nonceAdvance` alone over N) ⇒ refunded; anything else ⇒ undecided. A supervised `withdrawal-payout-resolution` loop (10 s; per-call RPC timeouts; bounded concurrency) settles from those facts, fires queued payouts when the lane frees, and kills an undecided payout after `PAYOUT_KILL_AFTER_MS` (5 min); the operator's `not_paid` broadcasts the kill (409 `kill_pending` until it is finalized). A busy or unavailable nonce lane sends nothing: the withdrawal stays `pending` and queued (`relay_withdrawal_payout_queue`). The blockhash send path never re-signs after an expiry any more (#885's re-sign class is gone; `earlierBroadcastsDead` is always true for a send that resolves). Removed: `getFreshSignatureVerdict`, `FreshSignatureVerdict`, `FRESH_WINDOW_*`, the fresh-verdict sweep, `recordPayoutAttempt` and `runFreshVerdictSweep`; `relay_withdrawal_payout_attempts` gains `kind`, `nonce_account`, `nonce_value`, `final_status`, `final_slot`, `final_checked_at` (idempotent ALTERs). Declared stuck set: a consumed nonce whose payout and kill statuses are both unreadable forever, and payouts claimed before durable nonces (no nonce to kill) — never refunded, `paid` accepted.
