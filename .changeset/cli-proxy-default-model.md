Motebit Cloud gets a model it serves, by the proxy's own rule (#654 cold review R1 + R2). `--provider proxy` with no `--model`, and a config `default_provider: proxy` with no `default_model`, now run `DEFAULT_PROXY_MODEL` instead of falling through to the Anthropic BYOK default, which the Cloud proxy refused on the first turn. `motebit daemon` and `motebit serve` now apply the persisted provider/model exactly as the interactive CLI does (a provider flip re-derives an implicit model; a `default_model` the active provider can't serve yields).

On `proxy`, every pre-flight — launch `--model`, a stored `default_model`, and `/model <id>` — now runs `motebitCloudAdmission` from `@motebit/sdk`, the same function the Cloud proxy runs on every request, alias step included. Widened: class aliases and legacy dated ids the proxy resolves (`claude-opus`, `claude-opus-4-20250115`, `gpt-4o`, `gemini-flash`, …) and `llama-3.3-70b-versatile` are accepted on launch, kept verbatim when stored, and switchable with `/model`. Narrowed, by name: `motebit --provider proxy --model <id>` now exits 1 at startup with the repair when `<id>` is outside the Cloud catalog after alias resolution (e.g. `claude-sonnet-5`, `claude-opus-4-7`, an unknown id) — the proxy refuses every model turn for exactly those ids (451/400), so no invocation that could reach a model is refused; such a stored `default_model` yields to `DEFAULT_PROXY_MODEL` with a notice naming Motebit Cloud. `--provider=x` / `--model=x` / `--max-tokens=x` (the `=` spelling) now outrank the persisted config the same as the spaced spelling.
