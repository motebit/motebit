**A task served by several bodies of one identity runs at most once.** The relay hands a task to every serving socket of an identity (the CLI daemon, the desktop app, a browser tab, a phone), and its claim grants exactly one of them — but every body used to send `task_claim` and run the task at once, so each serving body executed it. `motebit run` and `motebit serve` now route task frames through the shared `TaskClaimCoordinator` (`@motebit/runtime`, used by every surface): claim, run only on the relay's grant, drop the task on `task_claim_rejected`, and renew the claim's lease while running. A granted claim means the task may have started, so it is never handed to a second body: a claimer that dies, is partitioned, or runs out of a phone's background budget leaves the task claimed and **undetermined** — the delegator's poll reports `undetermined: { reason: "claimer_lost" }` instead of a pending or failed task — and only that body's own late signed result resolves it. A result from any other device of the identity is refused.
