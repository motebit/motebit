**The relay refuses to start without a master token.** Every master-token gate was installed only when `MOTEBIT_API_TOKEN` was non-empty, so a relay booted without it served the memory, state, audit and goals exports and the admin fee and withdrawal dashboards, and accepted `POST /api/v1/admin/freeze`, with no authentication. `createSyncRelay` now throws when `apiToken` is missing or blank, and the production config builder throws on an unset or empty `MOTEBIT_API_TOKEN`, so the process exits before listening with a repair message. The decision is ONE function, `resolveRelayAuthPosture(env)`, which `server.ts`, library embedders and `motebit relay up` all call. The only way to run open is the local-development opt-in `MOTEBIT_RELAY_INSECURE_NO_AUTH=1`, honoured only when `NODE_ENV` (trimmed, lowercased) is exactly `development` or `test` — any other value, unset included, refuses to boot, token or not — and an unrecognised opt-in value refuses too. The opt-in reaches the relay only as the posture that function mints (config `authPosture`); a relay wired with no token and no minted posture installs sealed gates that answer 401, never open ones. It logs `relay.insecure_no_auth` at warn level. A route-table test now enumerates every `/api/v1/admin/*` handler from the router and requires 401 without credentials, and a boot matrix (entry point × `NODE_ENV` × token × opt-in) probes every protected route of every cell that boots.
