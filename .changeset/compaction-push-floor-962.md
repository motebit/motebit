**Quitting no longer deletes events the relay has not received** (#962). Compaction runs when the REPL or daemon stops, and that happens before sync-on-exit. It used to delete every event below the newest one without checking whether the relay had confirmed them. An event written just before quitting could be deleted before it was pushed, so it never reached your other devices. Compaction now stops at the relay's confirmed push cursor. With more than one relay, it stops at the lowest cursor. If the cursor cannot be read while sync is configured, nothing is compacted. A later process also keeps these events before it reconnects, because the relay stream is saved next to the cursor when sync connects. Without a relay, compaction works as before. If one relay holds more than one push cursor (an encrypted and a raw process), the most advanced one counts, so an old cursor never stops compaction for good. And because the CLI always has a relay configured, compaction also waits when no cursor was ever saved.

**The REPL's sync is now accepted by the relay without a configured token.** Plain `motebit` with no `MOTEBIT_API_TOKEN` or `--sync-token` sent every event push without a credential, so the relay refused it. The push cursor never moved, and with compaction waiting on that cursor, `motebit.db` stopped compacting. The REPL now signs its sync requests with a device token from your identity key, as the daemon does, and introduces the device to the relay before its first push. When the relay refuses a push, the REPL says so in one line (`Sync failed (continuing offline): …`) at start, on exit and on `/sync`; it used to stay silent.

**`motebit run` and `motebit serve` now push their events to the relay** (#962 round 4). Both daemons connected to their relay, but only the REPL ever pushed events: the REPL at start and exit, and on `/sync`. A machine that ran only the daemon never sent its events, and with compaction waiting for the relay, `motebit.db` grew with nothing said about it. Now each daemon pushes right away and then every 30 seconds, using the same device-token transport. `serve` pushes when it serves over HTTP with a relay. `motebit delegate` pushes while its plan runs and once more before it exits. The REPL also pushes every 30 seconds during a session, not only at start and exit. When a push is refused because the relay does not know the device yet (for example, the relay was unreachable when the REPL started), the device is introduced to the relay again and the push is retried at once. A failure is reported in one line when it starts, and again when sync resumes. A daemon with no relay configured (`run` without a sync URL, `serve` over stdio) no longer counts as configured, so its compaction no longer waits for a relay that does not exist.

**Whether sync is configured is now remembered by the database, not decided by each process** (#962 round 5). A `motebit.db` could lose events when a process configured for a relay wrote them but never saved a push cursor. For example, the REPL's first launch creates the identity and then attaches to a daemon that is already running. A process with no relay (`serve` over stdio, or `run` without a sync URL) opened the same database next, counted itself as unconfigured and compacted those events away. When the REPL pushed later, the relay received almost none of them. Now every process configured for a relay records that fact in `motebit.db` for its identity: the REPL (including its identity setup), `delegate`, `run` and `serve` with a relay, and `serve` over stdio when a relay is named for it by `--sync-url`, `MOTEBIT_SYNC_URL` or `sync_url` in config.json. Every process that opens the database keeps unpushed events from then on, whatever its own configuration. Only a database whose identity was never configured for sync compacts freely. If that record cannot be read, nothing is compacted.

**Text a relay sends back is now cleaned before it is printed.** A relay's response body used to reach the terminal verbatim, for example `Device registration: <status> <body>`. A hostile relay could use it to change the window title or clear the screen. Control characters and escape sequences are now removed, and the text is cut to about 200 characters.

**The push loop backs off while the relay is unreachable.** Each process used to try every 30 seconds for as long as the relay was down, which is 2,880 requests a day. Consecutive failures now wait longer each time, with random jitter, up to 10 minutes. The first success returns the loop to 30 seconds. One line is still printed when the failure starts and one when sync resumes.

Stated cost: compaction waits for the relay to confirm. If the relay is never reached (offline, or a machine that never connects) or keeps refusing the push (a revoked device, a bad token), nothing is compacted and `motebit.db` grows until a push is confirmed. Once any process for an identity has been configured for a relay, this applies to every process on that database, including a daemon with no relay of its own. That is the trade the fix makes: an event is never deleted before the relay has it.
