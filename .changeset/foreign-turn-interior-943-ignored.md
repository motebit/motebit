A foreign principal's turn is served none of the owner's interior (#943). Sibling: `foreign-turn-interior-943.md` (the `motebit` package that bundles this runtime).

- `@motebit/ai-core`: `runTurnStreaming` reads the per-turn mark (`deps.foreignPrincipal`) once. Every owner-store read of the loop (memory probe, pinned memories, similarity recall, the Layer-1 memory index, recent events) moved into one function, `recallOwnerInterior`, which a foreign turn skips. So a foreign turn embeds nothing against the owner's graph and writes no retrieval back to it. The turn's options are floored once by `floorForeignTurnOptions` (new `foreign-turn.ts`), which drops every `owner_interior` field and projects the `[Now]` snapshot to its substrate alone. `TURN_OPTION_FOREIGN_CLASS` classifies every `TurnOptions` field, so adding a field without deciding whether it is the owner's is a compile error.
- `@motebit/ai-core` (round 5): the loop's own context is floored too. `CONTEXT_PACK_FOREIGN_CLASS` (`satisfies Record<keyof ContextPack, …>`) classifies every pack field. `floorForeignContextPack` is applied to every pack a foreign turn sends. It makes `current_state` (the owner's live state vector) neutral and drops `behavior_cues`, and `previousCues` is reclassified `owner_interior`.
- `@motebit/runtime`: both `sendMessage*` doors build the owner's blocks in one helper, `ownerInteriorForTurn`. For a foreign turn it reads and selects nothing: no trust-graph read, no self-model, no curiosity hints, no skill selection, and no `SkillLoaded` event. It passes only the session snapshot. `recallMemoriesForTool` (the `recall_memories` backend) returns `[]` on a foreign turn. The private `buildSelfAwareness` wrapper is inlined.
- `@motebit/mcp-server`: the owner's memories are served only to the owner principal. `servedPrincipal(extra, transport)` counts only the local stdio session as the owner. HTTP callers are never the owner, whatever they present: a `mid`=self token is not proof, because the owner signs those for workers, servers and the relay, and `verifyCallerToken` binds no audience and keeps no replay cache. `motebit_recall` and the `motebit://memories` resource refuse a non-owner with `OWNER_ONLY_REFUSAL`, with no memory content and no dep call. They pass the verdict to `queryMemories` / `getMemories` as a new optional third or second argument. Every memory-read dep (`service.ts`, and the CLI's) opens with the new `assertOwnerPrincipal`. The `motebit_query` description no longer claims memory context.
- `@motebit/runtime`: the runtime-host `memory_recall` read frame refuses unless the attached frontend names `principal: "owner"`.
- Delegation receipts are attributed AT CAPTURE, never by draining a shared bucket.
  - `@motebit/mcp-client`: `McpClientAdapter` keeps no receipt array. `executeTool` returns a verified `motebit_task` call's receipt ON its result (`delegation_receipt`, type `ToolResultWithDelegationReceipt`). `getAndResetDelegationReceipts` is removed.
  - `@motebit/runtime`: `SimpleToolRegistry.execute(name, args, destination = OWNER_ACT)` takes the carried receipt off the result and records it for the caller's destination. A turn's loop deps thread its key (`loopDepsForTurn`). Every other caller is an owner door: `invokeLocalTool`, PlanEngine steps via `getLoopDeps()`, the approval queue, taps, attached frontends and the serve path. The single-writer hold opens and closes each turn's collector (`TurnDelegationReceipts`). A task's receipt gets only its own turn's hires, through the new `onDelegationReceipts` option on `sendMessageStreaming`.
  - `@motebit/runtime`, owner record: owner receipts go to the owner's record, whose intake credits them to the owner. That credit is the trust bump, `ChainTrustComputed`, graph edges and latency, through the new exported `absorbDelegationReceipts`, shared with `handleAgentTask`. `delegate_to_agent` returns its receipt on its result instead of stashing it. `AgentTaskHandlerDeps` loses `getMcpAdapters` and `getAndResetInteractiveDelegationReceipts`. `getAndResetInteractiveDelegationReceipts()` drains the owner's record only.
  - Services: `code-review`, `research`, `summarize` and `web-search` read each sub-hire's receipt from the call's result instead of draining the adapter.
- `@motebit/runtime`: tools from servers the owner connected (`registerExternalTools`, the runtime's `mcpServers`) are registered `localOnly` through `registerOwnerConnectedTool`. It `replace`s, so a same-named tool a surface merged earlier is overwritten as owner-connected. A foreign turn never sees or calls them, and `motebit serve` never re-serves them. `registerExternalTools` marks a same-named tool that is already registered as `localOnly` (new `SimpleToolRegistry.markLocalOnly`), so the floor does not depend on registration order. The CLI REPL owns one connection per config-listed server: it no longer hands `mcp_servers` to the runtime, and registers each server's tools with `registerExternalTools` as `mcp:<name>` (`apps/cli/src/mcp-config-wiring.ts`). So `/mcp remove` disconnects the only connection.
- `@motebit/runtime`: a turn's sink now receives `{ receipt, trustCredited }`, so a hire already credited where it was made is credited once. The owner-record intake credits trust only for a receipt that verifies, under the stored key or else its embedded `public_key`.
- `@motebit/mcp-server`: the `motebit://state` resource (the owner's live state vector) is owner-only, like the memories resource (`OWNER_ONLY_STATE_REFUSAL`).
- `check-memory-source-canonical` gains scan (e), which locks both chokepoints and the runtime helper textually, scan (f), which locks every MCP memory-read handler, dep and the frame and that HTTP is never the owner, and scan (g), which locks attribution at capture. That covers no shared receipt array or drain anywhere, the one take site, the caller's destination, the threaded turn key, and no turn sink or task path reaching the owner record. It also locks owner-connected tools as `localOnly`. `check-gates-effective` gains probes for scans (d), (e), (f) and (g); the (g) probe is the cold reviewer's own `drainOwner`-in-sink injection.
