A foreign principal's turn is served none of the owner's interior (#943). Sibling: `foreign-turn-interior-943.md` (the `motebit` package that bundles this runtime).

- `@motebit/ai-core`: `runTurnStreaming` reads the per-turn mark (`deps.foreignPrincipal`) once. Every owner-store read of the loop (memory probe, pinned memories, similarity recall, the Layer-1 memory index, recent events) moved into one function, `recallOwnerInterior`, which a foreign turn skips. So a foreign turn embeds nothing against the owner's graph and writes no retrieval back to it. The turn's options are floored once by `floorForeignTurnOptions` (new `foreign-turn.ts`), which drops every `owner_interior` field and projects the `[Now]` snapshot to its substrate alone. `TURN_OPTION_FOREIGN_CLASS` classifies every `TurnOptions` field, so adding a field without deciding whether it is the owner's is a compile error.
- `@motebit/runtime`: both `sendMessage*` doors build the owner's blocks in one helper, `ownerInteriorForTurn`. For a foreign turn it reads and selects nothing: no trust-graph read, no self-model, no curiosity hints, no skill selection, and no `SkillLoaded` event. It passes only the session snapshot. `recallMemoriesForTool` (the `recall_memories` backend) returns `[]` on a foreign turn. The private `buildSelfAwareness` wrapper is inlined.
- `@motebit/mcp-server`: the owner's memories are served only to the owner principal. `servedPrincipal(extra, transport)` counts only the local stdio session as the owner. HTTP callers are never the owner, whatever they present: a `mid`=self token is not proof, because the owner signs those for workers, servers and the relay, and `verifyCallerToken` binds no audience and keeps no replay cache. `motebit_recall` and the `motebit://memories` resource refuse a non-owner with `OWNER_ONLY_REFUSAL`, with no memory content and no dep call. They pass the verdict to `queryMemories` / `getMemories` as a new optional third or second argument. Every memory-read dep (`service.ts`, and the CLI's) opens with the new `assertOwnerPrincipal`. The `motebit_query` description no longer claims memory context.
- `@motebit/runtime`: the runtime-host `memory_recall` read frame refuses unless the attached frontend names `principal: "owner"`.
- `@motebit/runtime`: delegation receipts are collected per turn by a new `TurnDelegationReceipts`. The single-writer hold opens and closes each turn's collector. A task's receipt gets only its own turn's hires, through the new `onDelegationReceipts` option on `sendMessageStreaming`. `AgentTaskHandlerDeps` loses `getMcpAdapters` and `getAndResetInteractiveDelegationReceipts`. `invokeCapability` taps go to the owner's record and never into an in-flight turn. `getAndResetInteractiveDelegationReceipts()` now drains the owner's record only.
- `check-memory-source-canonical` gains scan (e), which locks both chokepoints and the runtime helper textually, scan (f), which locks every MCP memory-read handler, dep and the frame and that HTTP is never the owner, and scan (g), which locks the turn-scoped receipts. `check-gates-effective` gains probes for scans (d), (e) and (f).
