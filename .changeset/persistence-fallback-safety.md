Make the sql.js fallback database driver safe. It now saves atomically (temp file in the same directory → fsync → rename → directory fsync), so a crash, kill or full disk mid-save keeps the previous snapshot instead of truncating the database; refuses to open an existing database it cannot read (only a missing file means "new"), one that fails `PRAGMA quick_check`, or one with a non-empty native `-wal` beside it; holds a single-writer lock (`<db>.sqljs-lock`) so a second process cannot overwrite the first's snapshot; and saves on exit, SIGINT and SIGTERM. `openMotebitDatabase` falls back only when the native `better-sqlite3` module itself fails to load — a locked, corrupt or unmigratable database is now an error, not a silent switch to a stale copy — and only for read-only commands (`ps`, `logs`, `runs`, `runs show`, `goal list`, `goal outcomes`, `doctor`'s coverage report). Every command that writes (the REPL, `run`/daemon, `delegate`, `approvals`, `grant`, `halt`, `credentials`, `attest`, `goal add/remove/enable`, `sync`, `export`, `up`, `skills`) requires commit-durable storage and refuses the fallback with a repair instruction (`pnpm rebuild better-sqlite3`). The fallback still loses up to ~1s of acknowledged writes on a hard crash; it says so.
