`motebit --grant <id>` and `motebit serve --direct --grant <id>` no longer present a standing grant on a turn where a relay's revocation feed could not be read. A timeout, a network error, a redirect, a non-2xx answer or a body that is not the feed used to count as "nothing revoked", so a grant revoked on another machine still verified whenever the relay was unreachable. Now a failed pull presents no grant for that turn: in chat, money actions ask for approval; on a direct task they are refused. Each outage is announced once, in one line that names the failure and the relay's host (for example `HTTP 429 (relay.example)`), never a URL or an error's own text; after the relays answer again, a later outage is announced again.

Each turn the pull goes to every relay the identity is known to use: the relay the session talks to now (in chat, `/connect <url>` moves it), plus the named relay re-read each turn (`--sync-url` > `MOTEBIT_SYNC_URL` > config `sync_url`). If any of them fails, the grant is withheld; their records are merged. Before, the pull ignored `--sync-url` and preferred the config file over the environment. `motebit grant revoke` propagates to the named relay resolved the same way. With no relay known anywhere, or when every pull succeeds, nothing changes. An `http://` relay URL that redirects to `https://` withholds until the URL is corrected. Not covered: a relay that omits a revocation, or a wrong relay URL (the feed is unsigned).
