`motebit --grant <id>` and `motebit serve --direct --grant <id>` no longer present a standing grant on a turn where the relay's revocation feed could not be read. A timeout, a network error, a redirect, a non-2xx answer or a body that is not the feed used to count as "nothing revoked", so a grant revoked on another machine still verified whenever the relay was unreachable. Now a failed pull presents no grant for that turn: in chat, money actions ask for approval; on a direct task they are refused. Each outage is announced once, in one line that names the failure (for example `HTTP 429`); after the relay answers again, a later outage is announced again. The pull now goes to the relay the session itself uses (`--sync-url` > `MOTEBIT_SYNC_URL` > config `sync_url`); before, it ignored `--sync-url` and preferred the config file over the environment. `motebit grant revoke` propagates to the relay resolved the same way. With no relay named, or when the pull succeeds, nothing changes. Not covered: a relay that omits a revocation, or a wrong relay URL (the feed is unsigned).
