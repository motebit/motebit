# @motebit/crypto

Sign and verify every Motebit artifact. Apache-2.0 (permissive floor), Layer 0, **zero runtime monorepo dependencies** (`@motebit/protocol` is an optional, type-only peer — rule 7). `@noble/ed25519` is bundled.

## Rules

1. **`src/suite-dispatch.ts` is the ONLY file permitted to call `@noble/ed25519` primitives directly.** `check-suite-dispatch` enforces this across `packages/crypto/`, `services/`, and `apps/`. Every verifier routes through `verifyBySuite`.
2. **Explicit escape hatches use a named waiver.** `// crypto-suite: intentional-primitive-call` on the same line exempts a single call (reviewer-gated). Don't waive broadly.
3. **Missing or unknown `suite` values are rejected fail-closed.** No legacy-no-suite acceptance path. Adding a new suite means a new `SuiteId` entry in `@motebit/protocol` and a new dispatch arm here.
4. **Self-verification is the contract.** A third party must be able to verify any Motebit artifact (identity file, execution receipt, credential, credential anchor, revocation, succession) with only this package and the signer's public key. No relay contact, no external system required.
5. **Permissive-floor purity.** No imports from BSL packages. `check-deps` enforces.
6. **Merkle inclusion verification lives in `merkle.ts`; never re-inline.** One canonical primitive (`verifyMerkleInclusion`), four consumers today (`credential-anchor.ts` for credential-anchor proofs, `witness-omission-dispute.ts` for `inclusion_proof` evidence against horizon certs' `federation_graph_anchor.merkle_root`, `agent-settlement-anchor.ts` for per-agent settlement inclusion proofs — the SCITT/RFC 6962 worker-audit verifier, and `federation-settlement-anchor.ts` for inter-relay settlement inclusion proofs — the peer-audit verifier that closed the RFC 6962 arc). Same algorithm — binary tree, odd-leaf promotion (no duplication), SHA-256 leaves — same fail-closed contract. Inline `toHex` / `fromHex` / `concat` helpers are gone from the consumers; future Merkle-anchored artifacts add a further consumer that imports the same primitive. Sibling-boundary doctrine for the phase 4b-3 commit-2 extraction. (Leaf/node domain separation per RFC 6962 §2.1 — `0x00`/`0x01` tags — is the `MerkleTreeVersion` agility axis the verifiers now dispatch on; see `docs/doctrine/merkle-tree-hash-versioning.md`.)
7. **Every package a published `.d.ts` imports is declared.** The emitted types import `@motebit/protocol`, so it is an OPTIONAL `peerDependency` (`workspace:^`) — type-only, never in `dependencies`, so the runtime stays at zero deps and npm never auto-installs it. `lint:pack` runs `scripts/consumer-typecheck.mjs`: it packs this package plus every declared dep, installs them into a scratch consumer, and type-checks with `skipLibCheck: false` (and fails on any runtime `dependencies` entry). The changesets config sets `onlyUpdatePeerDependentsWhenOutOfRange` — without it every protocol minor would force a crypto MAJOR. Bundling the protocol types into this package's `.d.ts` was rejected: protocol's `unique symbol` brands and enums are nominal, so a duplicated copy would make `MotebitId` from crypto unassignable to `MotebitId` from protocol.

Post-quantum migration (ML-DSA-44, ML-DSA-65, SLH-DSA) is a new `SuiteId` plus a new dispatch arm — not a wire-format break. The protocol plane is crypto-agile; rails that happen to share Ed25519 (e.g. Solana) are coincidental and remain their own concern.
