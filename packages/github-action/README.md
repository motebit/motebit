# motebit-verify GitHub Action

Verify the Ed25519 signature of a `motebit.md` agent identity file in your CI pipeline. Fails the check if the signature is invalid or the file is missing.

The Action runs the canonical [`motebit-verify`](https://www.npmjs.com/package/@motebit/verify) CLI (`@motebit/verify`, Apache-2.0), pinned to a published version for CI reproducibility. It verifies with [`@motebit/crypto`](https://www.npmjs.com/package/@motebit/crypto) under the hood and bundles the canonical hardware-attestation platform leaves.

## Quick Start

```yaml
# .github/workflows/verify-identity.yml
name: Verify Agent Identity
on: [push, pull_request]

jobs:
  verify:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: motebit/motebit/packages/github-action@main
```

## Full Example

```yaml
name: Agent Identity Gate
on:
  pull_request:
    paths: ["motebit.md", "agents/*/motebit.md"]

jobs:
  verify:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: motebit/motebit/packages/github-action@main
        id: identity
        with:
          path: motebit.md

      - name: Annotate PR
        if: success()
        run: |
          echo "### Agent Identity Verified" >> $GITHUB_STEP_SUMMARY
          echo "- **motebit_id:** ${{ steps.identity.outputs.motebit-id }}" >> $GITHUB_STEP_SUMMARY
          echo "- **public_key:** ${{ steps.identity.outputs.public-key }}..." >> $GITHUB_STEP_SUMMARY
```

## Inputs

| Input             | Default      | Description                    |
| ----------------- | ------------ | ------------------------------ |
| `path`            | `motebit.md` | Path to the identity file      |
| `fail-on-missing` | `true`       | Fail if the file doesn't exist |
| `node-version`    | `20`         | Node.js version                |

## Outputs

| Output       | Description                          |
| ------------ | ------------------------------------ |
| `valid`      | `true` if signature is valid         |
| `motebit-id` | The `motebit_id` from the file       |
| `public-key` | First 16 hex chars of the public key |

## What it checks

1. The `motebit.md` file exists at the specified path
2. The YAML frontmatter is well-formed per [motebit/identity@1.0](https://github.com/motebit/motebit/blob/main/spec/identity-v1.md)
3. The Ed25519 signature is cryptographically valid over the frontmatter bytes

A valid signature proves the file hasn't been tampered with since it was signed by the agent's private key.

## How it works

The Action runs `npx --yes @motebit/verify@<pinned> <path> --expect identity --json` (the pin lives in [`action.yml`](./action.yml)), which:

- Parses YAML frontmatter between `---` delimiters
- Extracts the signature from the `<!-- motebit:sig:<suite>:<signature> -->` comment
- Dispatches by `SuiteId` (cryptosuite-agile — post-quantum migrations don't change this wire format)
- Verifies the signature against the `identity.public_key` field
- Validates key succession chains if present

`--expect identity` makes any other signed artifact type a failure rather than a pass. The CLI's exit codes map to the outputs: `0` → `valid=true` with `motebit-id` / `public-key` read from the structured result; `1` (signature invalid) or `2` (unreadable, or not an identity file) → `valid=false` and the step fails.

**Network.** Verification itself is offline and deterministic — no network calls are made to check the signature. The Action does use the network once to install the pinned CLI from the npm registry via `npx` (and `actions/setup-node` to install Node). For a fully offline runner, pre-install `@motebit/verify` at the pinned version into the npm cache.

**Guarded in CI.** The monorepo's CI runs this Action, exactly as a consumer would, against an identity file freshly generated by the repo's own generator and against a tampered copy — so a pin that stops accepting current identity files fails CI instead of failing consumers.

## Troubleshooting

**"motebit.md not found"** — Check the `path` input. Default is `motebit.md` in the repository root.

**"signature verification failed"** — The file was modified after signing. Re-sign with `npx create-motebit` or `motebit export`.

**"could not be verified"** — The file is not a readable motebit identity file (the CLI exited `2`), for example a different signed artifact type at that path.

**Slow first run** — The action downloads `@motebit/verify` via npx on first use. Subsequent runs in the same job use the npm cache.
