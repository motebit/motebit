# @motebit/wallet-solana

Sovereign Solana USDC rail. Layer 1, BSL. The reference `SovereignRail` implementation.

## Rules

1. **`custody: "agent"` on `SolanaWalletRail` — relay never signs agent transfers.** The motebit's Ed25519 identity key IS its Solana address (mathematical accident: Solana uses Ed25519 natively). `Keypair.fromSeed(identitySeed)` derives the wallet from the existing 32-byte identity seed. No second key, no custodial provider, no vendor approval. The deleted `DirectAssetRail` (2026-04-08) was the wrong shape because the relay was signing **on behalf of an agent** — the agent's funds, the relay's signature. Do not re-introduce that pattern.
2. **Compile-time rejection of relay registration.** `SettlementRailRegistry.register()` in `services/relay` accepts only `GuestRail`. Registering a `SovereignRail` is a `tsc` error. The negative proof lives in `services/relay/src/__tests__/custody-boundary.test.ts`. Do not widen.
   - **`OperatorSolanaTransfer` is the operator-side companion**, NOT a `SovereignRail` and NOT a `GuestRail`. It is the relay-treasury primitive: the relay signs its own wallet's transfers from its own custody (the treasury wallet derives from the relay's Ed25519 identity by the same curve coincidence). It carries no `custody` label, never goes through `SettlementRailRegistry`, and is doctrinally indistinguishable from the relay paying a vendor invoice from its treasury wallet. The two roles use the same `Web3JsRpcAdapter` underneath because the adapter is custody-neutral by design — the custody distinction lives at the construction-site type (`SolanaWalletRail` vs `OperatorSolanaTransfer`), not at the RPC primitive. Consumed today by `services/relay/src/budget.ts` Path 0 for same-party return of custody on user withdrawals to sovereign wallets. Path 0 payouts are durable-nonce transactions (#990): `sendPayout` signs `nonceAdvance` first over the treasury's seed-derived nonce account (`NONCE_ACCOUNT_SEED`, or `nonceSeedFor(suffix)` to rotate; created by `prepareNonceLane` when absent, TAKEN OVER when a system-owned 0-byte or Uninitialized account squats the public address, and reported `squatted` — never used — when anything else does), `broadcastNonceKill` consumes a nonce value, and `getFinalizedStatus` reports only a per-status `finalized` confirmation — absence or a status below finality is `unknown`, never evidence.
3. **RPC is a swappable adapter.** `SolanaRpcAdapter` is the boundary. Default `Web3JsRpcAdapter` wraps `@solana/web3.js` + `@solana/spl-token`. Tests run against the adapter interface with no network. Do not import `@solana/web3.js` outside the adapter.
4. **The agent pays its own SOL fees.** Sovereign means you pay your own gas. Do not add a relay-subsidy path. There is no automatic top-up: a transfer below `GAS_FLOOR_LAMPORTS` throws `InsufficientSolForGasError` before signing.
   - **Never sign a transaction someone else built.** The Jupiter swaps (`jupiter.ts`) signed API-returned bytes with the identity key, unvalidated; they now refuse through `refuseJupiterSwap` until an intent-bound validator exists. `check-third-party-tx-signing` fails on a decoded transaction (or raw network bytes) reaching a signer outside its (empty) `VALIDATOR_MODULES`. It cannot see a transaction built locally from third-party-supplied instructions (Jupiter Jupiter's swap-instructions endpoint), so never assemble one: build transactions locally from the owner's intent.
5. **`SolanaMemoSubmitter` is the reference `ChainAnchorSubmitter`.** Credential Merkle-batch anchoring and individual revocation events use it. Fire-and-forget — chain submission failure never blocks the artifact it anchors. Its `network` has no default (#954): it is read lazily from the RPC's genesis hash before the first write (`SolanaNetworkResolver` in `network.ts`, `solana:<first 32 chars>`, every read time-bounded; resolved and mismatch are cached, a failed read is retried by the next write), and a declared network the RPC contradicts refuses every write, permanently. The same law binds `OperatorSolanaTreasuryReconciler` (`chain` required, must be a Solana CAIP-2 id): a CAIP-2 label is derived from the cluster written to, never assumed.
6. **A rail built with `spendableMints` signs only for those mints.** `spendableMints` is an optional, construction-time allowlist on `SolanaWalletRail` / `createSolanaWalletRail` (and on `Web3JsRpcAdapter`): a frozen copy, no setter. With one, `send`, `sendBatch` and `buildP2pPayment` throw `RailSpendRefusedError` (`code: "rail_spend_refused"`) as their FIRST statement — before the gas check, before any RPC read, before anything is signed — unless the adapter's PARSED mint (`SolanaRpcAdapter.usdcMint`, never the raw config string) is listed; the adapter repeats the check first thing in `sendUsdc` / `sendUsdcBatch` / `sendUsdcDurable`. **An allowlist over an adapter that reports no mint refuses every spend** (fail closed). Absent ⇒ unrestricted: the CLI and the apps pass none and behave as before. The mint, not the cluster, is the predicate because it is part of what gets signed (a transfer names token accounts derived from it), so the check needs no network read and does not trust the RPC. `confirmSend` reads the refusal as `absent` (nothing was sent), matching it by class or by `name` + `code` together (`isRailSpendRefusal`); `spendRefused` is the read-only answer a caller consults before a meter commits spend. **Who sets it:** `@motebit/molecule-runner` alone, to its one constant `MOLECULE_SPENDABLE_MINTS` (`[USDC_MINT_DEVNET]`), on every rail it builds — so a first-party molecule cannot sign a mainnet-USDC transfer under any configuration. Widening that list is a reviewed change to the constant, locked by `check-molecule-spend-containment`; do not add an env- or config-sourced allowlist here.
7. **Curve coupling is convention, not protocol law.** Future Ed25519-native chains (Aptos, Sui) satisfy the same `SovereignRail` interface. Non-Ed25519 chains would require a separate adapter under the same interface — identity and wallet stay architecturally decoupled in `spec/settlement-v1.md §3.3`.

The previous custodial rail (`DirectAssetRail` + `PrivyWalletProvider`) was deleted 2026-04-08. The relay does not sign agent transfers.
